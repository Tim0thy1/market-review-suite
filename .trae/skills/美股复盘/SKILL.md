# 美股复盘

## 概述

这是一个端到端的**美股每日深度复盘**技能。它整合了三个核心能力：

1. **数据采集** — 运行 `Sentinel_Daily_Pro.py`，通过 Moomoo API（行业板块、概念板块、24小时快讯、要闻）+ WeStock Data（指数/ETF/个股K线、宏观数据）+ **CBOE 期权链（自选股期权链、期权情绪指标、期权墙/Zero Gamma）** + **FRED 信用利差（CDS 信用风险代理）** 多数据源获取全维度数据，输出 Excel 文件
2. **联网信息增强** — 搜索华尔街机构研报、关键宏观事件、个股重大新闻、**关键人物发言（特朗普/美联储官员/马斯克/X财经网红/著名机构）与彭博社等财经媒体观点**，补充数据之外的背景信息
3. **分析报告生成** — 按照"宏观 → 资金流 → 行业 → 个股 → 交易结构"五层视角，严格按时间顺序进行因果还原，生成包含 ECharts 可视化图表的自包含 HTML 报告

**输出格式由客户端类型自动决定**：电脑客户端（内置浏览器可浏览 HTML）→ 生成自包含 HTML 报告；手机 App（暂不支持 html）→ 直接输出文字版（Markdown 纯文本）。见「输出格式自动判断」章节。

## 输出格式自动判断（强制 · 先于一切分析）

> **⛔ 硬性规则**：Agent 在开始任何数据采集、分析写作之前，**第一步必须先判断本次复盘指令来自哪个客户端**。判断错误会导致输出格式不符（把 HTML 发给不能浏览的手机，或把文字版发给想看图表的电脑），因此本规则强制优先执行。

### 判断依据（从用户指令本身识别）

| 判断信号 | 判定为电脑客户端 | 判定为手机 App |
|---------|-----------------|---------------|
| **指令明示** | 用户说"生成网页/HTML报告/图表/浏览器看" | 用户说"文字版/不要HTML/手机上看/纯文本" |
| **指令载体特征** | 在聊天中输入长结构化指令、引用文件路径、要求"可视化/图表/报告" → 倾向电脑 | 用户提到"手机上/App/打开不方便/看不到网页" → 倾向手机 |
| **历史行为** | 用户过往对 HTML 报告有正向反馈、要求生成报告文件 | 用户过往要求"直接输出文字/太长了/手机看" |
| **上下文痕迹** | 会话中涉及 `computer://` 链接、报告文件目录、浏览器预览 | 会话要求"精简/压缩/手机友好" |

**核心判断原则**：
1. **用户指令明确时，以用户明示为准**（用户说"文字版"就输出文字，说"HTML"就输出HTML）
2. **用户未明示时**：若无任何手机线索，默认按**电脑客户端**处理（输出 HTML 报告，附带 `computer://` 文件链接）；若指令中出现手机相关线索（"手机""App""打开不方便""看不到网页"），则按手机处理，**直接输出文字版 Markdown，不生成 HTML 文件**
3. 当从对话上下文中能判断出用户设备时，跟随上下文的稳定推断

### 两种输出模式的分工

| 模式 | 适用客户端 | 交付物 | 特点 |
|------|-----------|--------|------|
| **HTML 模式** | 电脑客户端（内置浏览器） | 自包含 `.html` 文件（ECharts 图表） | 可视化、图表丰富，交付 `computer://` 链接 + 聊天摘要 |
| **文字版模式** | 手机 App（暂不支持 HTML） | 纯文本 Markdown（直接展示在聊天中） | 信息密度高、可一键复制，图表用文字/表格代替 |

### 文字版模式的写作要求

当判定为手机 App（文字版）时，**必须完整保留 16 章分析框架的全部维度**，只是以纯 Markdown 文字方式呈现而非 HTML：

- **16 章结构一个不能少**：从章零到章十四，每一章的核心分析维度都必须覆盖。文字版与 HTML 版的区别仅在呈现形式，不在分析深度
- **图表转表格**：HTML 中的 ECharts 折线图/柱状图/雷达图，在文字版中改为 Markdown 表格呈现（指数数据用表格、涨跌幅排序用表格、多空辩论用结构化文字）
- **HTML 卡片转 Markdown 段落**：HTML 中的数据卡片、结论卡片，在文字版中改为 `###` 标题 + 加粗关键数据 + 连续自然段
- **核心分析章节（章零、一、二、三、五、七、十四）使用连续自然段**：一个完整逻辑链写成一个段落，避免一句话一个段落的碎片化
- **每个事实/结论只讲一次**：不同章节之间不重复同一数据点，章一讲过的数据章五引用时一句话带过
- **因果传导链保留**：每条关键新闻的归因仍须讲清四层（改变什么预期→谁受益为何→资金先手还是跟风→逻辑能否持续），用连贯自然段呈现

## 工作流程

### 第一步：确定目标交易日期

根据用户请求确定复盘日期：
- 如用户指定日期（如"复盘7月31日美股"），使用该日期
- 如用户未指定，判断最近一个完整交易日：
  - 如果当前是北京时间周一至周五上午（美东时间前一日收盘后），使用前一个交易日
  - 如果当前是北京时间周六至周日，使用最后一个周五
  - 如果是美东时间盘中（北京时间21:30-次日04:00），只做盘中概览

### 第二步：运行数据采集脚本

```bash
cd 'd:\AI\trae work\stock\美股'
python Sentinel_Daily_Pro.py --date YYYY-MM-DD -o US_Market_Pro_YYYY-MM-DD.xlsx
```

**参数说明**：
- `--date YYYY-MM-DD` — 指定交易日期（用于宏观数据）
- `-o filename.xlsx` — 指定输出文件名
- `--skip-moomoo` — 跳过 Moomoo 数据（只用 WeStock）
- `--skip-westock` — 跳过 WeStock 数据（只用 Moomoo）
- `--skip-options` — 跳过 CBOE 期权链采集
- `--skip-fred` — 跳过 FRED 信用利差采集
- `--fred-key KEY` — 指定 FRED API key（默认读取环境变量 `FRED_API_KEY`，免费注册：https://fred.stlouisfed.org/docs/api/api_key.html）
- `--watchlist PATH` — 指定期权链采集列表文件（默认读取 `stock.options.core.list`：MAG7+AI科技巨头+股指ETF共27只；如需全量144只传 `stock.list`）
- `--output-dir result` — 输出目录（默认 result）

脚本执行后会在 `result/` 目录下生成 Excel 文件，包含以下 18 个 Sheet：

| Sheet | 数据源 | 说明 |
|-------|--------|------|
| 行业_成份股 | Moomoo | 行业板块及成份股涨跌幅 |
| 概念_成份股 | Moomoo | 概念板块及成份股涨跌幅 |
| Day_News_快讯 | Moomoo | 24小时快讯（逐条） |
| Important_News_要闻 | Moomoo | 重要要闻精选 |
| 指数_K线 | WeStock | 纳指/标普/道指/罗素2000/VIX 近20日K线 |
| 七巨头_K线 | WeStock | MAG7 近20日K线 |
| 行业ETF_K线 | WeStock | 26个行业ETF近20日K线 |
| 半导体个股_K线 | WeStock | 13只半导体个股近20日K线 |
| AI基础设施_K线 | WeStock | 10只AI相关个股近20日K线 |
| 金融个股_K线 | WeStock | 5只金融股近20日K线（含JPM/GS等） |
| 能源个股_K线 | WeStock | 3只能源股近20日K线 |
| 医疗个股_K线 | WeStock | 5只医疗股近20日K线 |
| 加密概念股_K线 | WeStock | 4只加密概念股近20日K线 |
| 宏观数据 | WeStock | 美国宏观指标 |
| 期权情绪指标 | CBOE | 自选股 P/C OI Ratio、P/C Volume Ratio、加权IV、最大OI行权价 |
| 期权墙_科技巨头 | CBOE | 科技巨头 Call Wall / Put Wall / Zero Gamma / Gamma环境 |
| 期权链_自选股 | CBOE | 自选股期权链明细（bid/ask/IV/OI/Volume/Greeks，仅1年行权期） |
| 信用利差_CDS代理 | FRED | ICE BofA 信用利差（IG/HY/BBB/CCC OAS），CDS 信用风险代理 |

**期权链采集说明**：
- 期权链采集列表默认读取工作区根目录 `stock.options.core.list`（每行一个代码，`#` 开头为注释；MAG7+AI科技巨头+股指ETF共27只）
- 指数期权 CBOE 不支持（SPX/IXIC/DJI 返回403），自动映射到对应 ETF：`^SPX→SPY`、`^IXIC→QQQ`、`^DJI→DIA`
- 期权链仅保留前后1年行权期，控制数据量
- 每只标的计算期权情绪指标：Put/Call OI Ratio、Put/Call Volume Ratio、按成交量加权的 Call/Put IV、最大 OI 行权价
- 注意：深度实值/虚值期权的单合约 IV 字段可能异常（CBOE 未标准化），分析时以加权 IV 为准

### 第三步：读取并解析数据

使用 Python 脚本读取 Excel 文件，提取关键数据：

```python
import pandas as pd

# 读取K线数据
df_indices = pd.read_excel('result/US_Market_Pro_YYYY-MM-DD.xlsx', sheet_name='指数_K线')

# 提取关键指标
# - 各指数当日涨跌幅、成交量变化
# - MAG7 涨跌幅排名
# - 行业ETF表现排序（涨跌幅前5/后5）
# - 板块成份股涨跌分布
# - 快讯/要闻时间线
```

**关键数据提取要点**：
- 指数：当日收盘价、涨跌幅、5日趋势、成交量变化
- 七巨头：各股涨跌幅、谁是领涨/领跌
- 行业ETF：哪些行业涨/跌、幅度、板块轮动趋势
- 个股：半导体/AI/金融/能源/医疗/加密各板块表现
- 宏观数据：利率、CPI/PPI、就业、GDP等指标
- 新闻：按时间顺序整理快讯和要闻，识别关键驱动事件
- 期权情绪：读取 `期权情绪指标` Sheet，提取各标的 P/C OI Ratio、P/C Volume Ratio、加权IV、最大OI行权价
- 期权墙：读取 `期权墙_科技巨头` Sheet，提取科技巨头（MAG7等）的 Call Wall（上方阻力）、Put Wall（下方支撑）、Zero Gamma、Gamma 环境（Long/Short）、距 Zero Gamma 距离。重点判断：现价是否持续高于 Zero Gamma（Long Gamma 环境墙体有效；Short Gamma 环境墙体失效，不适合依托墙体逆势交易）
- 期权链：读取 `期权链_自选股` Sheet，识别异常放量的期权合约（单日成交量/持仓量异常）、平值IV变化
- 信用利差：读取 `信用利差_CDS代理` Sheet，提取 IG/HY/BBB/CCC 各档利差的最新值、周变化、趋势（利差走阔=信用风险上升/风险偏好下降，收窄=风险偏好回升）

#### 多时间维度分析（新增 · 核心）

> 复盘不能只看单日，必须拉宽时间维度。所有数据解读都要同时看三个时间窗口：

| 时间窗口 | 关注重点 | 解决的问题 |
|---------|---------|-----------|
| **当日（1D）** | 涨跌幅、成交量、资金流向、新闻驱动 | 今天发生了什么 |
| **近5日（5D）** | 趋势方向、板块轮动持续性、量能变化趋势 | 当前的短期趋势是什么 |
| **近20日（20D）** | 中期趋势、均线系统、支撑/阻力位、累计资金流向 | 中期方向如何，是否值得参与 |

**数据提取要求**（在原有基础上追加）：
- 指数：当日涨跌幅 + 5日涨跌幅 + 20日涨跌幅 + 5日/20日均线位置
- 七巨头：当日涨跌幅 + 5日趋势（连续上涨/下跌天数） + 20日相对强弱
- 行业ETF：当日涨跌幅排名 + 5日累计涨跌幅排名 + 20日趋势判断
- 成交量：当日成交量 vs 5日均量 vs 20日均量
- 龙头股：当前价格 vs MA5/MA20/MA50 位置关系
- 概念板块：近5日/20日累计涨幅TOP10

5. **地缘政治** — 搜索当日重大地缘政治事件
6. **行业动态** — 搜索AI、半导体、加密货币等热点行业新闻

9. **小资金交易策略** — 搜索当前市场环境下$2000-3000资金规模的可操作策略和标的

	### 第五步：生成分析报告

#### 核心分析框架

**市场 = 状态（State） + 触发器（Trigger） + 资金响应（Flow）**。禁止将行情简单归因于当天的新闻，必须先判断市场原有的仓位状态和信念底色。

使用 **"五层视角"** 框架进行分析，严格按**时间顺序进行因果还原**，禁止"拿着结果找原因"：

**宏观 → 资金流 → 行业 → 个股 → 交易结构**

#### 分析方法论（强制四步法）

每个核心判断必须经过以下四步，缺一不可：

1. **观察事实** — 盘面发生了什么，数据是什么（先写盘面事实，再写推导，再写结论）
2. **排除其他解释** — 为什么不是其他常见解释（排除法，避免"拿着结果找原因"）
3. **给出最可能解释** — 基于排除后的剩余选项，给出最合理的因果链，明确标注"证据等级"（高/中/低）
4. **附反证条件** — "如果这个判断是错的，盘面应该出现什么信号"（让读者可以自行验证判断的有效性）

#### 盘面归因方法论强化（消息泄漏度分级 + 因果传导链强制化）

> **⛔ 核心原则：禁止"消息—涨跌"的简单关联。** 复盘每条关键新闻时，不得只写"发布X数据 → 利好 → 涨"这种没有任何信息量的废话，必须讲清传导机制，并内部判断该消息发布前资金有无可能已先手布局。

**一、消息泄漏度分级（内部评估，不写进报告）**

分析者在给某条新闻做归因时，先在内部评估：**这条消息在正式发布前，资金有无可能提前知情、先手买入？**

| 消息类型 | 泄漏渠道 | 资金提前反应的可能性 |
|---------|---------|--------------------|
| 央行/联储决议、会议纪要、政府政策 | 高（起草/吹风/路演阶段易提前泄露，卖方会提前铺观点） | **高**——资金常提前埋伏 |
| 公司财报、订单、扩产、回购、评级调整 | 中高（有内幕可能，但公司公告前消息渠道多） | **中高**——警惕信息抢跑 |
| 官方定时宏观数据（CPI/PCE/非农） | 低（严格保密，但市场有预测共识） | 有限——主要看"实际 vs 预期"的差 |
| 突发地缘/黑天鹅（冲突、灾难、单日爆雷） | 极低（无法预知） | 极低——无法提前埋伏 |

**内部评估方法**：若某板块在消息正式公开前已出现逆势异动、放量上涨、先知资金持续流入，则大概率是"消息已被抢跑"；此时归因时直接写"资金在消息公开前已提前潜伏布局"，而不要机械地按"消息发布时间=资金反应时间"来归因。

**二、因果传导链强制化（外部呈现）**

报告中对每条关键新闻的归因，必须讲清四层，缺一不可，禁止A-B硬套：

1. **这条消息改变了什么预期** — 资金原本怎么想（原状态State），消息如何扭转/强化这个预期
2. **谁最受益、为什么是它** — 传导到哪条产业链/哪个环节/哪个公司，受益机制是什么（如"利率下行→长久期资产估值↑→软件SaaS DDOG/CRM受益"）
3. **资金是先手还是跟风** — 内部判断资金是否已在消息发布前先手买入；若是，写明"从某板块某时点的逆势走强可见"
4. **此逻辑能否持续** — 是预期博弈还是有实质兑现，下一交易日还能不能继续讲

**写作呈现**：不要把"泄漏度""抢跑""先知资金"等词汇直接写进报告作为过程解释；应直接呈现判断结果与证据。例如：写"资金在X消息公开前已提前布局，从该板块盘中逆势走强可见"，而不是"这条消息泄漏度较高所以资金提前买入"。

#### 叙事竞争分析框架

每次分析必须区分两个层面：

- **局部定价权** — 某条叙事在板块层面赢了（如"AI物理基建"叙事推动半导体设备逆势翻红）
- **全局定价权** — 某条叙事在指数层面赢了（如"宏观利率"叙事压制大盘指数收跌）

必须回答：哪条叙事赢得了局部定价权？哪条赢得了全局定价权？为什么？

| 二 | 宏观锚点与风险偏好 | 利率、美元、原油、黄金、VIX 等宏观指标变化。包含"宏观资产背离/共振分析"：黄金与原油的背离说明什么、DXY/10Y/2Y变化对各类资产的影响、判断这是风险偏好增强还是避险升温 |
| 三 | 市场主线与资金流向 | 行业轮动方向（当日+5日+20日排名）、资金净流入/流出。必含5个子模块：①主线判定、②行业内部拆解（半导体拆到设备/逻辑芯片/存储/光模块）、③资金去向逻辑链（防御轮动/利率交易/短线避险/中期配置）、④做空动能拆解（真跌还是假摔）、⑤叙事竞争（局部定价权vs全局定价权） |
| 四 | 暗线与多空伏击点 | 三条暗线：①多头水面下的涟漪（连阳重心上移的标的）、②空头高位裂痕（放量滞涨/破位标的）、③分歧中的生还者/掉队者（逆势飘红/逆势收阴的标的） |
| 四·五 | 期权情绪与期权墙分析（新增 · 必写） | ①期权情绪：基于 `期权情绪指标` Sheet 分析自选股期权市场情绪（P/C OI Ratio 与 Volume Ratio 背离/共振、加权IV、异常放量合约）。②期权墙：基于 `期权墙_科技巨头` Sheet 分析科技巨头（MAG7等）的 Call Wall（上方阻力）、Put Wall（下方支撑）、Zero Gamma、Gamma 环境。**必须附带 Long/Short Gamma 概念解释卡**（见下），每个判断标注"证据等级"，并给出反证条件。若无期权数据，如实标注"期权数据源未覆盖" |

**Long/Short Gamma 概念解释卡（必写 · 用户记不住概念，报告必须自带解释）**：

> **Zero Gamma**：使市场总 Gamma 为 0 的标的价格，是 Long Gamma 与 Short Gamma 环境的分界线。
>
> **Long Gamma 环境（现价 > Zero Gamma）**：
> - 含义：市场整体 Gamma 为正。做市商在标的价格上涨时**卖出**、下跌时**买入**（反向对冲，逆势操作）
> - 影响：①**抑制波动**——做市商反向对冲形成"阻尼器"，涨多了被卖压压制、跌多了被买盘托住，价格倾向在箱体内震荡；②**墙体有效**——Call Wall / Put Wall 具备持续、可反复博弈的支撑/阻力作用，适合依托墙体高抛低吸；③**波动率倾向下降**——IV 通常被压制
>
> **Short Gamma 环境（现价 < Zero Gamma）**：
> - 含义：市场整体 Gamma 为负。做市商在标的价格上涨时**买入**、下跌时**卖出**（正向对冲，追涨杀跌）
> - 影响：①**放大波动**——做市商追涨杀跌形成"放大器"，上涨加速上涨、下跌加速下跌，容易走出单边趋势；②**墙体失效**——墙体局部对冲流量与全局 Gamma 流动方向同向，缺少反向制衡力量，即便出现短暂假突破/假破位脉冲行情也仅是一次性调仓，难以形成稳定震荡箱体；③**不适合依托墙体逆势摸顶/抄底**；④**波动率倾向上升**——IV 通常被推高
| 四·六 | 信用利差分析（新增 · 必写） | 信用利差：读取 `信用利差_CDS代理` Sheet，分析 IG/HY/BBB/CCC 各档利差的最新值与周变化。利差走阔=信用风险上升/风险偏好下降（利空成长股），收窄=风险偏好回升。结合当日美股走势判断"利率-信用-权益"传导链。每个判断标注证据等级与反证条件。若 FRED 未配置 key，如实标注"信用利差数据源未配置" |
| 五 | 盘面成因拆解 | 按时间线还原，每条事件包含"事实—证据链—因果机制—量化影响—交叉验证—前后关联"六层。开头增加"State→Trigger→Flow"总览，说明当天市场原有状态、遇到什么触发器、资金如何响应 |
| 六 | 叙事如何映射到不同资产 | 同一叙事在不同板块/个股上的差异化影响。包含叙事交互分析、证据层级判定、反事实推演。增加"局部定价权vs全局定价权"对比和叙事权重量化 |
| 七 | 多空力量对比（TradingAgents辩论式） | 三幕辩论式：①多头陈述（核心信仰、挑票还是全买、追主线还是做轮动）、②空头反击（押注什么、通过什么路径做空、是否存在轧空风险）、③边际力量判断（空头刚开始发力/空头衰竭/多头开始接管） |
| 八 | 24小时关键信息筛选 | 对每条信息做"影响力评分+证据强度+对应价格变动+信息类别（剧情推进/放大器/政策风向标/背景噪音）"四维评估，按影响力排名。**必须纳入"关键人物发言与机构观点监控"模块的采集结果**（特朗普/美联储官员/马斯克/X财经网红/机构研报/彭博社观点），每条标注来源。末尾包含"未被市场定价的信息"专项分析 |
| 九 | 市场状态更新库 | 两个核心模块：①被钝化/证伪的旧叙事（什么前期逻辑今天彻底不管用了）、②正式接管的新定价锚（市场今天开始真正交易什么新逻辑） |
| 十 | 前瞻观察与风险 | 未来1-3个交易日关键观察变量。包含主线延续情景、主线反转情景（从哪里开始失真）、做空/防御触发条件（Short Triggers） |
| 十一 | 风险可控的交易标的建议 | 基于"小资金+科技AI主线+10%止盈"策略的具体标的建议。增加交易映射（最优方向/最优表达方式/交易类型）、极值状态风控（是否规避0DTE和3倍杠杆ETF过夜） |
| 十二 | 科技/AI板块深度扫描 | 半导体/AI基础设施/AI应用/AI泛科技各细分板块多周期表现。增加板块内部驱动力文字分析，解释分化原因 |
| 十三 | 仓位管理建议 | 当前建议仓位、入场节奏、止盈触发条件、止损执行纪律、空仓条件 |
| 十四 | 结论式总结 | 公众号/朋友圈风格：白话观点化语言总结全天盘面，说明谁主导市场、接下来最值得盯什么。要有观点，不要中性废话 |

#### 关键写作原则

- **禁止"拿着结果找原因"** — 必须按时间顺序还原市场如何一步步走到最终K线，禁止先给结论再补理由
- **数据驱动** — 所有结论必须有数据支撑，避免主观臆断
- **机构观点** — 引用华尔街机构当日观点，标注来源（如"据高盛研报""据彭博社报道""据CNBC"）；关键人物发言（特朗普/美联储官员/马斯克等）必须标注发言人、场合与时间
- **因果链** — 宏观事件 → 市场解读 → 资金行为 → 价格变化，形成完整因果链，禁止"消息→涨跌"的简单关联，每条关键新闻须讲清传导机制（改变什么预期→谁受益为何→资金先手还是跟风→逻辑能否持续）
- **语言风格** — 专业、客观、简洁，使用中文。每个抽象术语必须在一句话内落到具体代码上（如"长久期资产=软件SaaS股DDOG/CRM"）
- **多时间维度原则** — 所有分析结论必须注明是哪个时间窗口的判断（1D/5D/20D），禁止用单日数据下中期结论
- **Bull/Bear双面呈现** — 每个判断必须有正反两面，模仿TradingAgents的多智能体辩论机制，让多头和空头各自陈述
- **风险优先原则** — 先评估风险再谈机会，每个交易建议必须包含明确的止损位和最大亏损额度
- **小资金适配原则** — 所有建议必须以$2000-3000资金规模为基准，考虑可买股数、分散度限制、交易成本影响
- **科技AI优先原则** — 标的筛选以科技/AI/AI泛科技为主线，其他板块仅作背景分析
- **10%止盈纪律** — 目标收益10%左右，达到后减仓至轻仓甚至空仓，情愿不亏
- **四步法原则** — 每个核心判断必须经过"观察事实→排除其他解释→给出最可能解释→附反证条件"四步，缺一不可
- **叙事竞争原则** — 每次分析必须区分"局部定价权（板块层面）"和"全局定价权（指数层面）"，并量化叙事权重
- **状态优先原则** — 市场 = 状态（State）+ 触发器（Trigger）+ 资金响应（Flow）。禁止将行情简单归因于当天的新闻，必须先判断市场原有的仓位状态和信念底色
- **期权情绪原则** — 期权分析必须区分 OI（存量仓位）与 Volume（当日情绪）：P/C OI Ratio 反映机构存量布局、P/C Volume Ratio 反映当日多空情绪，两者背离时说明"存量看多但当日情绪转空"或反之。加权IV 以成交量加权计算，避免深度实值/虚值合约的异常 IV 干扰。最大 OI 行权价是市场共识的支撑/阻力位
- **期权墙原则** — Call Wall（最大 OI 的 call 行权价）是上方阻力，Put Wall（最大 OI 的 put 行权价）是下方支撑。墙体仅在**全局 Long Gamma 环境**（现价持续高于 Zero Gamma）下具备持续、可反复博弈的支撑/阻力作用；在**全局 Short Gamma 环境**中墙体失效，假突破/假破位仅是一次性调仓，不适合依托墙体逆势摸顶/抄底。Zero Gamma 用 BS Gamma × OI 加权二分搜索计算，标注"近似值"
- **信用利差原则** — 信用利差（CDS 代理）是风险偏好的温度计：IG/HY/BBB/CCC 利差走阔=信用风险上升/风险偏好下降（利空高估值成长股），收窄=风险偏好回升。分析"利率-信用-权益"传导链：美债收益率上行+信用利差走阔=双重压制；收益率上行但利差收窄=经济向好/风险偏好仍强。禁止把信用利差变化与股市涨跌做简单关联，必须走因果传导链

- **连续阅读原则** — 关键分析段落（章零、一、二、三、十四）使用连续自然段写作，一个完整逻辑链写成一个段落，避免一句话一个段落。辅助数据可用卡片/表格，但核心分析不能碎片化

## 注意事项

- **数据时效性**：确保 `--date` 参数与复盘日期一致，否则宏观数据可能不匹配
- **Moomoo API 限流**：脚本已内置 0.5-1.5 秒随机延迟，但大量请求时仍可能被限流
- **WeStock 限流**：每 3 个请求后自动等待 1 秒
- **新闻采集**：快讯采集可能因网络波动中断，脚本有自动重试机制
- **关键人物发言监控**：每次复盘必须执行"关键人物发言与机构观点监控"必扫清单（7类对象），不可跳过；搜索结果为空时如实标注"当前数据源未覆盖"，不编造发言内容
- **期权链采集**：CBOE 接口对指数期权（SPX/IXIC/DJI）返回403，已自动映射到 ETF（SPY/QQQ/DIA）；部分小盘股可能无期权数据，脚本自动跳过并提示。期权链数据量大（每只标的数千条合约），仅保留前后1年行权期
- **期权墙计算**：Call Wall / Put Wall 基于最大 OI 行权价；Zero Gamma 用 BS Gamma × OI 加权二分搜索计算（近似值，标注使用）；Gamma 环境判断基于现价与 Zero Gamma 的相对位置。科技巨头（MAG7等）优先展示
- **FRED 信用利差**：需要免费注册 FRED API key（https://fred.stlouisfed.org/docs/api/api_key.html），通过环境变量 `FRED_API_KEY` 或 `--fred-key` 传入。未配置时脚本自动跳过并提示，报告如实标注"信用利差数据源未配置"
- **报告生成**：使用 `html-report` 技能时，确保从该技能目录复制 `echarts.min.js` 和字体文件
- **周一行情**：周一复盘需要覆盖周五到周日三天新闻，快讯采集时间范围会自动调整为72小时
